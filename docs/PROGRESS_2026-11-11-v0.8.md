# Bousy Player v0.8 — Implementation and qualification report

Date: **2026-11-11 (Asia/Manila)**

## Delivery

This iteration continues the independent Android video player based on the design and engine structure of Bousygram. The original `Vaydelux/Bousygram` repository is **unchanged**. Changes are source-only and have **not** been pushed or released as an APK.

## Implemented changes from v0.7

1. **Authoritative Continue Watching timeline:** native engines often publish duration and provisional timestamps before applying the saved seek. `PlayerSession` now acknowledges the requested resume only when its reported position is close enough (5s tolerance for keyframe seek) or when playback legitimately ends. Before acknowledgment, progress writes are skipped and an early engine switch preserves the target rather than reporting 0:00.
2. **Explicit Start Over:** an explicit seek to zero supersedes the pending resume, but progress is not persisted while an old nonzero timestamp is still displayed. An actual near-zero timeline is required to acknowledge the seek.
3. **Automatic MPV fallback:** reading container metadata alone is no longer treated as successful playback. A local AUTO MPV failure before playback begins may still fall back to Media3 once, preserving saved position; manual choices and HTTPS playback never auto-fallback on this condition.
4. **Avoid screen-on battery drain:** the surface `keepScreenOn` flag now follows playback intention and clears after Pause/EOF/error and on view release.
5. **External media intent hygiene:** HTTPS VIEW intent filters now require media MIME types. Ordinary browser links no longer match a scheme-only player intent. Users can still paste arbitrary approved HTTPS media URLs inside the app.
6. **History resiliency:** if Android's persisted-grant enumeration fails, Continue Watching is preserved instead of accidentally pruning all entries.
7. **Windows publishing option:** added an authenticated PowerShell script alongside the Bash script; both refuse to overwrite an existing standalone repository.

### Build environment blockers

Local environment has OpenJDK 21 and `kotlinc` CLI 1.9, but **no Gradle or Android SDK**. `services.gradle.org` could not be resolved from the container. Full Android build, lint, APK/DEX/ELF validation and device playback have **not** been run.

The dedicated `Vaydelux/BousyPlayer` repository was absent from GitHub on the most recent connected lookup, and the connected GitHub actions cannot create a repository. A user-authenticated GitHub CLI publish script is bundled for Windows PowerShell or Bash. The workflow is configured but **not executed**.
